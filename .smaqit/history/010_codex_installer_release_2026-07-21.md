## Problems Solved

- **No Codex installation target:** Added generated Codex agents and skills without changing the canonical root source model.
- **Reference migration contained stale assumptions:** Used the Daisy project for artifact shape but did not copy its older agent bodies or its unverified relative `skills.config` entries. Codex relies on native repository skill discovery instead.
- **PR release agent contained Copilot-only language:** Added platform-specific agent placeholders so Copilot retains `report_progress` while Claude Code and Codex use direct `git push` with current credentials.
- **Dogfooding and installer staging could be conflated:** Documented and enforced that root `.github/`, `.codex/`, and `.agents/` are committed workspace mirrors, while `installer/*` generated trees are the only embed staging inputs.
- **Installer verification was duplicated and incomplete:** Replaced fixed-path CI shell blocks with one reusable temporary-project smoke test that validates every installed artifact and uninstall behavior.
- **Initial sync counts reported zero:** Changed Makefile counts from parse-time expansion to runtime filesystem counts after copying.
- **Protected `.codex` workspace path blocked normal sync in this environment:** Re-ran the scoped sync with the required filesystem access; ordinary target installation remained unaffected.
- **Release pushes lacked an agent-usable credential:** SSH had no unlocked agent and HTTPS returned 403. The local release remained safe and fail-fast; the final remote commit, tag, and GitHub Release were later verified as present.

## Decisions Made

- **Keep `agents/` and `skills/` as the only canonical content sources.** Platform output must always be compiled from them and platform metadata, never edited in generated directories.
- **Use `installer/agents-codex/` and `installer/skills-codex/` only as ephemeral embed staging.** Root `.codex/agents/` and `.agents/skills/` exist exclusively for Codex dogfooding.
- **Do not install or overwrite `.codex/config.toml`.** Codex discovers project agents and repository skills without project configuration, and user configuration must remain untouched.
- **Omit generated `[[skills.config]]` entries.** Codex auto-discovers `.agents/skills`, while portable absolute paths are impossible and the reference project's relative-path assumption was not proven.
- **Generate Codex TOML from the shared agent body.** Required `name`, `description`, and `developer_instructions` fields are rendered and validated without duplicating agent behavior.
- **Use one smoke-test implementation locally and in CI.** `make smoke-test` is the authoritative end-to-end verification path.
- **Group history into four implementation commits plus one release commit.** Generator/installer behavior, testing, dogfooding mirrors, and documentation remain independently reviewable.
- **Release as v1.6.0.** Codex support is substantial new backward-compatible functionality, so a MINOR increment from v1.5.0 is appropriate.
